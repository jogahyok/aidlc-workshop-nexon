## 2. 기능 요구사항 (Functional Requirements)

### FR-01: 테이블 태블릿 자동 로그인 및 세션 관리
- 관리자가 초기 설정 1회 수행 (매장 식별자, 테이블 번호, 비밀번호)
- 로그인 정보 로컬 저장 후 자동 로그인
- 태블릿 전용 웹앱 + QR코드 모바일 접속 모두 지원

### FR-02: 메뉴 조회 및 탐색
- 카테고리별 메뉴 분류 및 표시
- 메뉴 상세 정보: 메뉴명, 가격, 설명, 이미지
- 카드 형태 레이아웃, 터치 친화적 UI (최소 44x44px)
- 카테고리 간 빠른 이동

### FR-03: 메뉴 옵션 시스템 (복합 옵션)
- 메뉴별 복합 옵션 지원 (사이즈, 토핑, 맵기 등)
- 옵션 그룹 정의 (필수/선택 구분)
- 옵션별 추가 가격 설정
- 옵션 선택에 따른 총 가격 실시간 계산

### FR-04: 장바구니 관리
- 메뉴 추가/삭제, 수량 조절
- 선택한 옵션 정보 포함
- 총 금액 실시간 계산
- 클라이언트 측 로컬 저장 (새로고침 시 유지)
- 장바구니 비우기

### FR-05: 주문 생성
- 주문 내역 최종 확인 (메뉴 + 옵션 + 수량 + 금액)
- 주문 확정 → 주문 번호 표시 → 장바구니 비우기 → 메뉴 화면 리다이렉트
- 주문 실패 시 에러 메시지 + 장바구니 유지
- 주문 정보: 매장 ID, 테이블 ID, 메뉴 목록(옵션 포함), 총 금액, 세션 ID

### FR-06: 주문 내역 조회
- 현재 테이블 세션 주문만 표시
- 주문 시간 순 정렬
- 주문별: 주문 번호, 시각, 메뉴/옵션/수량, 금액, 상태(대기중/준비중/완료)
- 매장 이용 완료 처리된 주문 제외

### FR-07: 매장 관리자 인증
- 매장 식별자 + 사용자명 + 비밀번호 입력
- 매장당 1개 관리자 계정
- JWT 토큰 기반, 16시간 세션 유지
- bcrypt 해싱, 로그인 시도 제한
- 브라우저 새로고침 시 세션 유지

### FR-08: 실시간 주문 모니터링
- SSE 기반 실시간 주문 업데이트 (2초 이내)
- 테이블별 그리드/카드 레이아웃
- 각 테이블 카드: 총 주문액, 최신 주문 미리보기
- 주문 카드 클릭 시 전체 메뉴 목록 상세 보기
- 주문 상태 변경 (대기중 → 준비중 → 완료)
- 신규 주문 시각적 강조

### FR-09: 테이블 관리
- 테이블 초기 설정 (번호, 비밀번호, 세션 생성)
- 주문 삭제 (확인 팝업 → 즉시 삭제 → 총 주문액 재계산)
- 테이블 세션 종료 (이용 완료 → 주문 내역 과거 이력 이동 → 리셋)
- 과거 주문 내역 조회 (날짜 필터링, 시간 역순)

### FR-10: 메뉴 관리
- 메뉴 CRUD (등록/조회/수정/삭제)
- 메뉴 정보: 메뉴명, 가격, 설명, 카테고리, 이미지(S3 업로드)
- 메뉴 옵션 그룹 관리 (옵션 그룹 생성, 옵션 항목 추가/수정/삭제)
- 메뉴 노출 순서 조정
- 필수 필드 및 가격 범위 검증

### FR-11: 다중 매장 지원
- 여러 매장이 하나의 시스템 공유
- 각 매장 독립 데이터 (메뉴, 테이블, 주문 분리)
- 매장별 독립적인 관리자 인증

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01: 성능
- 주문 접수 후 관리자 화면 표시: 2초 이내 (SSE)
- 메뉴 조회 API 응답: 500ms 이내
- 동시 접속: 중규모 (매장당 10~50 테이블)

### NFR-02: 보안
- JWT 토큰 기반 인증 (16시간 만료)
- 비밀번호 bcrypt 해싱
- 로그인 시도 제한 (brute-force 방지)
- HTTPS 필수 (TLS 1.2+)
- 입력값 검증 및 SQL Injection 방지
- CORS 정책 적용
- HTTP 보안 헤더 적용

### NFR-03: 가용성
- AWS 클라우드 배포
- 서비스 가동률 목표: 99.5%

### NFR-04: 확장성
- 다중 매장 지원 구조
- 매장 추가 시 코드 변경 없이 데이터만 추가

### NFR-05: 유지보수성
- 모듈화된 코드 구조
- API 문서화 (OpenAPI/Swagger)
- 구조화된 로깅

### NFR-06: 사용성
- 터치 친화적 UI (최소 44x44px 버튼)
- 반응형 디자인 (태블릿 + 모바일)
- 직관적인 네비게이션

## 4. 제외 범위 (Out of Scope)

requirements/constraints.md에 정의된 대로 다음 기능은 구현하지 않음:
- 결제 처리 (PG사 연동, 영수증, 환불, 포인트/쿠폰)
- 복잡한 인증 (OAuth, SNS, 2FA)
- 이미지 리사이징/최적화
- 알림 시스템 (푸시, SMS, 이메일, 소리)
- 주방 기능 (주방 전달, 재고 관리)
- 고급 기능 (분석, 리포트, 직원 관리, 예약, 리뷰, 다국어)
- 외부 연동 (배달, POS, 소셜, 지도, 번역)

## 5. 데이터 모델 개요

### 핵심 엔티티
- **Store**: 매장 정보 (매장 ID, 이름, 설정)
- **Admin**: 관리자 계정 (매장당 1개)
- **Table**: 테이블 정보 (매장 소속, 번호, 비밀번호)
- **TableSession**: 테이블 세션 (시작/종료 시각, 상태)
- **Category**: 메뉴 카테고리 (매장 소속, 이름, 순서)
- **MenuItem**: 메뉴 항목 (카테고리 소속, 이름, 가격, 설명, 이미지URL, 순서)
- **OptionGroup**: 옵션 그룹 (메뉴 소속, 이름, 필수/선택, 최소/최대 선택 수)
- **OptionItem**: 옵션 항목 (그룹 소속, 이름, 추가 가격)
- **Order**: 주문 (테이블 세션 소속, 주문 번호, 상태, 총 금액, 시각)
- **OrderItem**: 주문 항목 (주문 소속, 메뉴명, 수량, 단가)
- **OrderItemOption**: 주문 항목 옵션 (주문 항목 소속, 옵션명, 추가 가격)
- **OrderHistory**: 과거 주문 이력 (세션 종료 시 이동)

## 6. 접근 방식 요약

| 구분 | 고객용 | 관리자용 |
|------|--------|----------|

| **실시간** | 주문 상태 업데이트 (선택) | SSE 기반 주문 수신 |
