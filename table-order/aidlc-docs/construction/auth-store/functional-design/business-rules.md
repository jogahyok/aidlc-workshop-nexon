# 비즈니스 규칙 — Auth Service + Store Service

## Auth Service 비즈니스 규칙

### BR-AUTH-01: 관리자 인증
- 매장 코드(store_code) + 사용자명(username) + 비밀번호(password)로 인증
- 매장 코드로 매장 조회 → 해당 매장의 관리자 계정 조회 → 비밀번호 검증
- 비밀번호는 bcrypt로 해싱하여 저장 (cost factor: 12)
- 인증 성공 시 JWT Access Token 발급 (16시간 만료)
- 인증 실패 시 LoginAttempt 기록 후 에러 반환

### BR-AUTH-02: 테이블 인증
- 매장 코드(store_code) + 테이블 번호(table_number) + 비밀번호(password)로 인증
- 매장 코드로 매장 조회 → 테이블 조회 → TableCredential 비밀번호 검증
- 인증 성공 시 JWT Access Token 발급 (16시간 만료, type='table')
- 토큰에 store_id, table_id, table_number 포함

### BR-AUTH-03: 토큰 발급 규칙
- 알고리즘: HS256
- 만료: 발급 시점 + 16시간
- Payload: sub, store_id, type, table_number(table만), iat, exp
- Secret Key: 환경변수에서 로드 (최소 32자)

### BR-AUTH-04: 토큰 검증 규칙
- 서명 검증 (secret key)
- 만료 시간 검증 (exp > 현재 시각)
- type 필드 검증 (admin 또는 table)
- 검증 실패 시 401 Unauthorized 반환

### BR-AUTH-05: 로그인 시도 제한
- **대상**: 동일 (store_id + identifier + attempt_type) 조합
- **기준**: 최근 15분 이내 실패 횟수
- **제한**: 5회 실패 시 15분 잠금
- **잠금 판단**: 최근 15분 내 연속 실패 5회 이상이면 잠금 상태
- **잠금 해제**: 마지막 실패로부터 15분 경과 시 자동 해제
- **성공 시**: 실패 카운트 리셋 (이전 실패 기록은 유지하되 잠금 판단에서 제외)

### BR-AUTH-06: 비밀번호 정책
- 최소 8자 이상
- 관리자 비밀번호: 영문 + 숫자 조합 필수
- 테이블 비밀번호: 숫자 4~8자리 (태블릿 입력 편의)

## Store Service 비즈니스 규칙

### BR-STORE-01: 매장 등록
- API를 통한 매장 등록 (시드 스크립트 또는 슈퍼 관리자)
- 필수 필드: name, code
- code는 시스템 전체에서 고유
- 매장 등록 시 관리자 계정도 함께 생성 (username, password 필수)

### BR-STORE-02: 테이블 관리
- 매장 내 테이블 번호는 고유
- 테이블 등록 시 비밀번호 설정 필수 (TableCredential 생성)
- 테이블 삭제 시 관련 TableCredential도 삭제
- 활성 세션이 있는 테이블은 삭제 불가

### BR-STORE-03: 세션 시작 규칙
- **최초 세션**: 테이블 태블릿 로그인(인증 성공) 시 자동 생성
- **이후 세션**: 이전 세션 종료(이용 완료) 후, 해당 테이블의 첫 주문 생성 시 자동 시작
- 테이블당 active 세션은 최대 1개
- 이미 active 세션이 있으면 새 세션 생성하지 않음

### BR-STORE-04: 세션 종료 (이용 완료) 규칙
- 관리자만 세션 종료 가능
- 세션 종료 시:
  1. Order Service에 해당 세션의 주문 아카이브 요청 (HTTP)
  2. 아카이브 성공 시 세션 status를 'completed'로 변경
  3. completed_at에 현재 시각 기록
  4. 아카이브 실패 시 세션 종료 롤백 (에러 반환)
- 이미 completed 상태인 세션은 재종료 불가

### BR-STORE-05: 세션 종료 후 태블릿 동작
- 세션 종료 후 태블릿은 메뉴 화면 유지 (로그아웃하지 않음)
- 새 고객이 주문 시 새 세션이 자동 시작됨 (BR-STORE-03)
- 태블릿의 JWT 토큰은 유효한 상태 유지 (16시간 만료까지)

### BR-STORE-06: 현재 세션 조회
- 테이블의 현재 active 세션 조회
- active 세션이 없으면 null 반환 (아직 첫 주문 전 상태)
- 프론트엔드는 세션 유무로 "첫 주문" vs "추가 주문" 구분

## 에러 시나리오

### Auth Service 에러
| 코드 | 상황 | 응답 |
|------|------|------|
| AUTH_001 | 매장 코드 없음 | 404 "매장을 찾을 수 없습니다" |
| AUTH_002 | 사용자명/비밀번호 불일치 | 401 "인증 정보가 올바르지 않습니다" |
| AUTH_003 | 계정 잠금 상태 | 429 "로그인 시도가 제한되었습니다. N분 후 다시 시도하세요" |
| AUTH_004 | 토큰 만료 | 401 "세션이 만료되었습니다. 다시 로그인하세요" |
| AUTH_005 | 토큰 무효 | 401 "유효하지 않은 인증 정보입니다" |
| AUTH_006 | 테이블 없음 | 404 "테이블을 찾을 수 없습니다" |

### Store Service 에러
| 코드 | 상황 | 응답 |
|------|------|------|
| STORE_001 | 매장 코드 중복 | 409 "이미 존재하는 매장 코드입니다" |
| STORE_002 | 테이블 번호 중복 | 409 "이미 존재하는 테이블 번호입니다" |
| STORE_003 | 활성 세션 있는 테이블 삭제 시도 | 409 "활성 세션이 있는 테이블은 삭제할 수 없습니다" |
| STORE_004 | 이미 완료된 세션 종료 시도 | 409 "이미 종료된 세션입니다" |
| STORE_005 | 주문 아카이브 실패 | 502 "주문 이력 처리 중 오류가 발생했습니다" |
| STORE_006 | 매장 비활성 상태 | 403 "비활성 매장입니다" |
