# Frontend Business Rules

## 개요
프론트엔드에서 적용되는 비즈니스 규칙 정의입니다.
서버 측 검증과 별개로, 사용자 경험 향상을 위한 클라이언트 측 규칙입니다.

---

## 1. 장바구니 규칙 (Cart Rules)

### CR-01: 금액 계산
- **항목 소계** = (메뉴 기본가 + 선택 옵션 추가가 합계) × 수량
- **총 금액** = 모든 항목 소계의 합
- **금액은 항상 정수** (원 단위, 소수점 없음)
- **최소 금액**: 0원 이상 (음수 불가)

### CR-02: 수량 제한
- **최소 수량**: 1
- **최대 수량**: 99
- 수량 0이 되면 항목 자동 삭제

### CR-03: 장바구니 저장
- localStorage에 JSON 직렬화하여 저장
- **저장 키**: `cart_{storeId}_{tableId}`
- **만료 시간**: 세션 시작 시간 기준으로 관리
- 세션 종료 시 자동 삭제 (expiresAt 체크)
- 페이지 로드 시 만료 여부 확인 → 만료 시 장바구니 초기화

### CR-04: 장바구니 비우기
- 전체 비우기 시 확인 다이얼로그 표시
- 비우기 후 localStorage에서도 삭제

### CR-05: 동일 메뉴 처리
- 같은 메뉴 + 같은 옵션 조합 → 수량 증가
- 같은 메뉴 + 다른 옵션 조합 → 별도 항목으로 추가

---

## 2. 옵션 선택 규칙 (Option Rules)

### OR-01: 필수 옵션 검증
- `isRequired: true`인 옵션 그룹은 반드시 1개 이상 선택
- 필수 옵션 미선택 시 장바구니 추가 버튼 비활성화
- 미선택 필수 그룹에 시각적 강조 표시

### OR-02: 선택 수 제한
- `minSelections` 이상 선택해야 유효
- `maxSelections` 초과 선택 불가
- 최대 수 도달 시 나머지 옵션 비활성화 + 안내 메시지

### OR-03: 가격 실시간 반영
- 옵션 선택/해제 시 즉시 총 가격 업데이트
- 가격 표시 형식: `₩{금액.toLocaleString()}`

## 3. 인증 규칙 (Auth Rules)

### AR-01: Customer App 자동 로그인
- 앱 로드 시 localStorage에서 토큰 확인
- 토큰 존재 → `/auth/me` API 호출로 유효성 검증
- 유효 → 메뉴 화면으로 이동
- 무효/만료 → 에러 화면 표시 ("관리자에게 재설정 요청")
- 토큰 없음 → 에러 화면 표시

### AR-02: Admin App 로그인
- 매장 식별자 + 사용자명 + 비밀번호 입력
- 로그인 성공 → 토큰 localStorage 저장 + 대시보드 이동
- 로그인 실패 → 에러 메시지 표시
- 로그인 시도 제한 초과 → 잠금 안내 메시지 + 입력 비활성화

### AR-03: 토큰 관리
- 토큰 저장 키: `auth_token_{storeId}`
- 만료 시간 저장: `auth_expires_{storeId}`
- 페이지 로드 시 만료 체크 → 만료 시 로그아웃 처리
- API 호출 시 401 응답 → 자동 로그아웃 + 로그인 페이지 리다이렉트

### AR-04: 로그아웃
- localStorage에서 토큰/만료 시간 삭제
- 상태 초기화
- 로그인 페이지로 리다이렉트

## 4. 주문 규칙 (Order Rules)

### OD-01: 주문 생성 조건
- 장바구니에 1개 이상 항목 필수
- 유효한 세션 ID 필수
- 주문 확정 전 최종 확인 화면 표시

### OD-02: 주문 확정 플로우
1. 주문 확정 버튼 클릭
2. 최종 확인 화면 표시 (메뉴, 옵션, 수량, 총액)
3. 확인 버튼 클릭 → API 호출
4. 성공 → 주문 번호 표시 → 5초 후 메뉴 화면 리다이렉트 + 장바구니 비우기
5. 실패 → 에러 메시지 표시 + 장바구니 유지

### OD-03: 주문 상태 표시
- `pending` → "대기중" (노란색 배지)
- `preparing` → "준비중" (파란색 배지)
- `completed` → "완료" (초록색 배지)

### OD-04: 주문 내역 조회
- 현재 세션의 주문만 표시
- 시간 역순 정렬 (최신 주문 상단)
- 30초 간격 자동 갱신 (폴링)

---

## 5. Admin 주문 관리 규칙 (Admin Order Rules)

### AO-01: SSE 연결 관리
- 대시보드 진입 시 SSE 연결 시작
- 연결 끊김 시 자동 재연결 (3초 간격, 최대 5회)
- 5회 실패 시 수동 새로고침 안내
- 대시보드 이탈 시 SSE 연결 종료

### AO-02: 주문 상태 변경
- 상태 전이: pending → preparing → completed (단방향)
- 역방향 전이 불가
- 상태 변경 시 확인 없이 즉시 반영 (빠른 처리 우선)

### AO-03: 주문 삭제
- 삭제 전 확인 다이얼로그 필수
- 삭제 후 테이블 총 주문액 재계산
- 삭제 성공/실패 Toast 알림

### AO-04: 신규 주문 강조
- 새 주문 수신 시 해당 테이블 카드 하이라이트 (3초간)
- 카드 상단에 "NEW" 배지 표시 (클릭 시 제거)

## 6. 테이블 관리 규칙 (Table Management Rules)

### TM-01: 테이블 등록
- 테이블 번호: 1~999 정수
- 비밀번호: 4~20자
- 동일 매장 내 테이블 번호 중복 불가

### TM-02: 이용 완료 처리
- 확인 다이얼로그 필수 ("현재 세션의 모든 주문이 이력으로 이동됩니다")
- 처리 후 테이블 카드 초기화 (주문 0건, 금액 0원)
- 성공/실패 Toast 알림

### TM-03: 과거 내역 조회
- 날짜 범위 필터 (기본: 오늘)
- 시간 역순 정렬
- 세션 단위로 그룹핑

---

## 7. 메뉴 관리 규칙 (Menu Management Rules)

### MM-01: 메뉴 등록/수정 검증
- **메뉴명**: 필수, 1~50자
- **가격**: 필수, 100원 이상, 1,000,000원 이하, 정수
- **설명**: 선택, 최대 200자
- **카테고리**: 필수 선택
- **이미지**: 선택, 최대 5MB, jpg/png/webp

### MM-02: 옵션 그룹 검증
- **그룹명**: 필수, 1~30자
- **최소 선택 수**: 0 이상
- **최대 선택 수**: 최소 선택 수 이상
- **필수 그룹**: minSelections >= 1
- **옵션 항목**: 최소 1개 이상

### MM-03: 옵션 항목 검증
- **옵션명**: 필수, 1~30자
- **추가 가격**: 0원 이상, 100,000원 이하, 정수

### MM-04: 이미지 업로드
- Presigned URL 발급 → 직접 S3 업로드
- 업로드 중 프로그레스 바 표시
- 업로드 실패 시 재시도 버튼

### MM-05: 메뉴 순서 조정
- 드래그 앤 드롭 또는 위/아래 버튼
- 순서 변경 시 즉시 API 호출 (낙관적 업데이트)

## 8. UI/UX 규칙 (UI/UX Rules)

### UX-01: 터치 친화성
- 모든 인터랙티브 요소 최소 44x44px
- 버튼 간 최소 8px 간격
- 스와이프 제스처 지원 (카테고리 전환)

### UX-02: 로딩 상태
- API 호출 시 로딩 인디케이터 표시
- 스켈레톤 UI 사용 (메뉴 목록, 주문 목록)
- 버튼 클릭 후 중복 클릭 방지 (disabled 처리)

### UX-03: 에러 처리
- 네트워크 에러 → "네트워크 연결을 확인해주세요" Toast
- 서버 에러 (5xx) → "일시적인 오류입니다. 잠시 후 다시 시도해주세요" Toast
- 입력 검증 에러 → 해당 필드 하단에 인라인 에러 메시지
- 인증 에러 (401) → 자동 로그아웃 + 로그인 페이지

### UX-04: 반응형 디자인
- **Customer App**: 태블릿 (768px+) 우선, 모바일 (320px+) 지원
- **Admin App**: 데스크톱 (1024px+) 우선, 태블릿 (768px+) 지원
- 브레이크포인트: 320px / 768px / 1024px / 1280px

### UX-05: 접근성
- 모든 이미지에 alt 텍스트
- 폼 요소에 label 연결
- 키보드 네비게이션 지원
- 색상 대비 WCAG AA 기준 충족 (4.5:1)
- aria-label 적용 (아이콘 버튼)
